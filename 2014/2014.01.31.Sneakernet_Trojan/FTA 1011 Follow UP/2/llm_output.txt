Executive Summary
```
Previous General Dynamics Fidelis Cybersecurity Services (Fidelis) reporting, ref: Fidelis Threat
Advisory (FTA) #1011 dated 15 Jan 2014, introduced a malware system comprised of multiple
files that provided a means for intruders to discover and retrieve data from disparate computer
systems via removable storage devices. The malware system consists of at least two Portable
Executable (PE) files, one acting as a headquarters component and one acting as field unit or
agent component. The headquarters component infects drives connected to its host system with
the field unit component and retrieves data from the field unit on the infected drive’s return to the
headquarters host system. The field unit conducts reconnaissance and data collection in
accordance with particular commands.
Continuing analysis solidified the headquarters component’s Command and Control (C2) scheme.
The malware receives commands from a locally stored encrypted file.
This report describes select malware functionality with some granularity, provides extended detail
regarding the headquarters component’s C2 functionality, provides additional means of defensive
detection of this malware and describes some interesting aspects of the malware as a whole.
The Fidelis team updated Fidelis XPS [TM] advanced threat defense system with additional rules to
reflect current analysis findings associated with this malware.
```

### Analysis and Summary of the "Sneakernet Trojan" Malware

#### Overview
This report provides a detailed analysis of a sophisticated malware, referred to as the "Sneakernet Trojan," which consists primarily of two executable files: `netsat.exe` and `netui3.dll` (masquerading as `setup35.exe`). The malware is designed to spread through removable media and execute commands from an encrypted file stored on the local 'master' system. It includes various features aimed at stealth, obfuscation, and efficient data collection.

#### Key Components and Functionality

1. **netsat.exe Commands:**
   - **cpd**: Copies directories and their contents.
   - **cpr**: Copies files with size checking.
   - **der**: Deletes files and records activity in a log.
   - **dir**: Obtains a directory listing.
   - **ferry**: Writes malicious files to a hidden `RECYCLED` or `RECYCLER` directory. Files include `setup35.exe`, `Autorun.inf`, `~disk.ini` (renamed `netwi.drv`), and `act.te`.
   - **getres**: Iteratively copies files from the `RECYCLED/RECYCLER` directory on a target drive, deletes them from the source after copying. The source is assumed to be a drive used to collect data from one or more systems.

2. **netui3.dll (setup35.exe) Commands:**
   - **cp**: Copies files from one location to another.
   - **cpu**: Copies files and sets copied files as hidden.
   - **cptur**: Creates a directory and copies files to that directory.
   - **ddr**: Silently deletes a directory using shell file operations with specific flags (`FO_DELETE`, `FOF_NOERRORUI`, `FOF_NOCONFIRMATION`, `FOF_SILENT`).
   - **del**: Deletes a file.
   - **delu**: Deletes a file after setting attributes to normal.
   - **gd**: Recursively writes and reads encoded data to/from a directory.
   - **gdir**: Prints directory listings to `~FF323D.tmp`, encodes the data, and deletes the original file.
   - **gf**: Writes and reads encoded data to/from a file.
   - **gfover**: Determines if it has access to a file; may involve temporary file creation/rename operations.
   - **gi**: Collects system-related and possibly network-related information such as domains and system information.
   - **ndr**: Creates a directory.
   - **newend**: Closes a file that was opened for writing.
   - **newstar**: Sets normal attributes on a targeted file, deletes the file, opens the same filename as a binary file.
   - **wr**: Writes a string to a new file opened by the `newstar` command.
   - **runb**: Tries to run a targeted executable and checks for its existence every second for the next 15 minutes as long as it exists.
   - **rune**: Tries to run a targeted executable once.
   - **slf**: Generates a targeted file listing (e.g., `dir`) and copies the files in the list one by one.
   - **srf**: Copies files in a list one by one.
   - **srmf**: Uses `NetUseAdd` to connect to the `ipc$` share of a target host, creates a listing of files in the `c$`-`z$` shares of the target host, copies the files to a new location, and deletes the share connection added using `NetuseAdd`.

#### Malware Characteristics
1. **Stealth and Obfuscation:**
   - The malware attempts to remain quiet by implementing robust error handling.
   - It uses obscure file system paths and renames files to avoid detection.
   - The data collection folder is named 'Intel', which could be a deliberate or ironic choice.

2. **Environment Checking:**
   - The malware performs environment checks to prevent execution on systems with specific internal IP ranges (e.g., 10.x.x.x).
   - It prevents multiple iterations of itself on individual systems.
   - The malware has an expiration date, after which it will cease to function.

3. **Command and Control (C2):**
   - C2 is accomplished via providing commands in an encrypted file stored on the local 'master' system.
   - This suggests that intruders have either local or remote access to headquarters systems running `netsat.exe` or another application that automates remote C2 data/file retrieval.

4. **Data Exfiltration:**
   - Data collection functionality suggests that collected data might be gathered by the 'master' system for exfiltration.
   - The exact means of exfiltration are not yet determined but could involve additional code or mechanisms.

#### Conclusion
This report is based on reverse engineering and analysis of two PE files (`netsat.exe` and `netui3.dll`). While the analysis provides a comprehensive understanding of the malware's behavior, there may be additional components and artifacts that are currently inaccessible. The sophistication of the malware suggests a well-coordinated effort by actors who have taken significant steps to ensure its efficiency, effectiveness, and stealth.

Further analysis is ongoing, and any relevant additional information will be reported as soon as practicable.
