Loader runtime flow
The loader creates the mutex “{531511FA-190D-5D85-8A4A
279F2F592CC7}”, and waits up to two minutes if it is already present while
logging the message “IsLoaderAlreadyWork +”. The loader creates the
mutex “{531511FA-190D-5D85-8A4A-279F2F592CC7}”, and waits up to
two minutes. If it is already present while logging the message
“IsLoaderAlreadyWork +”, it extracts the resource BINARY 201. This
resource contains a wide string name of processes to inject into (i.e.
“explorer.exe”).
The loader makes a pipe named:
\.\pipe\Winsock2\CatalogChangeListener-%03x%01x-%01x
Where the “%x” parameter is replaced with the values 0xFFFFFFFF
0xEEEEEEEE 0xDDDDDDDD, or if it has successfully obtained the user’s
SID:
\.\pipe\Winsock2\CatalogChangeListener-%02x%02x-%01x
With “%x” parameters replaced with numbers calculated from the current
date and a munged user SID.
The pipe is used to communicate with the target process and the
transport module; the running code also reads its own image body and
writes it to the pipe. The loader then obtains the payload body from
resource BINARY 202. It finds the running process that matches the target
name, copies the buffer containing the payload into the process, then
starts its copy in the target process.
