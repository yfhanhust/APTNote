Because Elephant Beetle tends to exploit externally facing servers as the infiltration vector, the first servers that
were discovered at the target’s network are the web applications infrastructure and other servers that are related
to the compromised web application server and are accessible from their environment. In compromising the
mentioned internal servers, the group leveraged either compromised credentials they gathered or similar exploits
that were used to infiltrate the externally facing servers.
The access to and from the compromised assets are mainly achieved by the group’s web shells and Java tools,
both custom and open source, that provide tunneling capabilities of TCP packets and HTTP requests.
The threat group move laterally within the network mainly through web application servers and SQL servers,
leveraging known techniques such as Windows APIs (SMB/WMI) and ‘xp_cmdshell’, combined with custom
remote execution volatile backdoors.
For transferring tools and their outputs between compromised machines, the group leverage either a custom
Java uploader/downloader tool or various web shells that have file uploading/downloading capabilities.
Below is a high-level diagram that describes the lateral movement and access paths HTTP requests took, tunneled
from an internet-facing server to an internal web server, and from that to other internal servers in more inner zones.

The discovery phase
The attackers used and leveraged SQL servers that were accessible in the network, which usually are desirable
targets for attackers. During the discovery phase, the threat group scanned for internal MS-SQL servers. When
finding such servers, they attempted to leverage the ‘xp_cmdshell’ SQL procedure for executing commands
remotely on the server.
The threat interacted with the internal SQL servers in three ways:

Upload of a JSP/ASPX Web shell with SQL query capabilities to a web server that is accessible to the target

MS-SQL server. When this web shell was accessed, they provided the connection string and credentials of the
target MS-SQL server.

Upload of a custom Java tool for querying SQL databases, and execution with the Java binary residing on

the external server. The tool accepts as a parameter the Base64 encoded SQL query and path to a
configuration file that contains the connection string and credentials of the target MS-SQL server.

Use of the binary sqlcmd.exe for establishing SQL connection from a compromised SQL server to the target

SQL servers.

On the move
As the attack reaches its final stages, the Elephant Beetle team especially enjoys a good Windows environment.
When reaching a Windows domain environment, the threat group moved laterally and executed code remotely,
with both WMI and SMB – either directly (WMIC.exe binary) or with some supporting scripts to optimize their
operations.
For lateral movement activity via SMB, the group leveraged the open-source script Invoke-SMBExec.ps1, [12] which
is part of the Empire post exploitation framework. This PowerShell script allows remote code execution over
Windows machines via SMB mechanism, and is well-known to be used by threat groups for lateral movement.
The main tool that the group leveraged for lateral movement activity via WMI was a modified version of the open
source pen testing script WmiExec.vbs [13]  - a VBS script that allows code execution and remote control over
Windows machines via WMI mechanism.
The customization was probably done to evade detection, as the main modifications were renaming indicative
strings or variables, and adding the string replace function to dynamically transform a textual string.

saves incoming data to a target file path.

### Overview of Elephant Beetle Attack Techniques

The **Elephant Beetle** attack campaign showcases a sophisticated and multi-faceted approach to compromising networks. The attackers use a variety of tools and techniques to gain initial access, move laterally, maintain persistence, and exfiltrate data. Below is a detailed breakdown of the key methods and tools used by the Elephant Beetle group:

### Initial Access

1. **Web Shells:**
   - **JSP/ASPX Web Shells:** These web shells are uploaded to web servers and can be accessed via HTTP requests. They provide command execution capabilities, allowing attackers to run arbitrary commands on the server.
   - **SQL Query Capabilities:** Some of these web shells also allow for SQL query execution, enabling attackers to interact with internal SQL servers.

2. **Custom Java Tools:**
   - **s0b.jar:** This tool allows for local and remote SQL connections. It accepts a Base64 encoded SQL query and a configuration file containing the connection string and credentials.
   - **FileTransferServer.java:** A custom Java tool that binds to a socket and saves incoming data to a target file path, facilitating file transfer between compromised assets.

### Lateral Movement

1. **WMI (Windows Management Instrumentation):**
   - **Modified WmiExec.vbs:** The group uses a modified version of the open-source `WmiExec.vbs` script for remote code execution and control over Windows machines via WMI. Modifications include renaming strings and variables to evade detection.

2. **SMB (Server Message Block):**
   - **Invoke-SMBExec.ps1:** This PowerShell script, part of the Empire post-exploitation framework, is used for remote code execution over Windows machines via SMB.
   - **Web Application Directory Exploits:** Files are copied to accessible paths in web application directories and accessed as if they were legitimate web pages using custom VBS/Perl scripts.

### Persistence

1. **MS-SQL Servers:**
   - **Local Accounts Creation:** The threat group creates local MS-SQL accounts and assigns them the `sysadmin` role to maintain persistence.
   - **SQL Query Execution:** They use SQL queries to gather information about the SQL instance, including version and user passwords.

### Data Exfiltration

1. **File Transfer Tools:**
   - **Java FileTransferServer:** This tool is used to transfer files between compromised assets by binding to a socket and saving incoming data.
   - **VBS/Perl Scripts:** Custom scripts are used to download exfiltrated files from accessible paths on web servers.

2. **Web Shells with Upload/Download Capabilities:**
   - These web shells allow attackers to upload and download files, facilitating the staging of tools and data between different compromised assets.

### Reconnaissance

1. **SQL Server Interaction:**
   - **xp_cmdshell:** The `xp_cmdshell` SQL procedure is used to execute commands remotely on the server.
   - **Recon Commands:** The threat group runs reconnaissance queries to gather information about the SQL instance, including version and user passwords.

2. **Web Shell Access:**
   - Web shells are used to upload and execute custom tools, allowing for further exploration of the network.

### Techniques for Evasion

1. **File Hiding and Transfer:**
   - Files and outputs are relayed between compromised assets using various techniques, including custom Java tools and VBS/Perl scripts.
   - Exfiltrated files are placed in accessible paths on web servers, making them directly downloadable from the internet.

2. **Web Shell Usage:**
   - Web shells with file upload/download capabilities are deployed to stage files without the need for complex backdoor tools.

### Conclusion

The Elephant Beetle group demonstrates a high level of sophistication in their attack techniques, leveraging a combination of custom and modified tools to gain access, move laterally, maintain persistence, and exfiltrate data. By understanding these methods, organizations can better prepare and defend against similar threats.
