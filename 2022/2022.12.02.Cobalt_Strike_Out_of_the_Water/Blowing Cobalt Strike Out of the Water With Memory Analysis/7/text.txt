In-Memory Evasion
With our new hypervisor-based sandbox, we were able to detect the decrypted Cobalt
Strike SMB beacon in memory. This beacon loader even uses some in-memory evasion
features that create a strange sort of chimeric file. While it’s actually a DLL, the “MZ''
magic PE bytes and subsequent DOS header are overwritten with a small loader shellcode
as shown in Figure 1.
Figure 1. Disassembled Cobalt Strike beacon loader shellcode.
The shellcode loader jumps to the exported function DllCanUnloadNow, which prepares
the SMB beacon module in memory. To do this, it first loads the Windows pla.dll library
and zeroes out a chunk of bytes inside its code section (.text). It then writes the beacon
file into this blob and fixes the import address table, thus creating an executable memory
module.

To sum up, the beacon loader and the beacon itself are the same file. Parts of the PE
header are used for a shellcode that jumps to an exported function, which in turn creates
a module of itself inside a Windows DLL. Finally, the shellcode jumps to the entry point
of the beacon module to execute it in memory.
As discussed, there is no way for us to detect this beacon of our KoboldLoader sample
successfully unless we can peer inside memory during execution.
