CONTEXT
In late December 2018, LEXFO was contacted by a mobile video game company following multiple
infections. The company was alerted of outgoing malicious traffic to a known Lazarus C&C that was being
monitored.
About 5 machines were identified as infected in the network at the time. LEXFO immediately asked
for RAM and disk dumps of the infected systems, as well as all captured encrypted traffic and began
investigating.

SWPSVC (Stage 1)
The analyzed malware sample of the group Lazarus is a “stage 1” reconnaissance malware which
implements Remote Administration Tool features.
The analyzed sample is a DLL library which is loaded by the ~~svchost~~ service, as it is registered as an
~~AUTO_START~~ service for persistence. The delivery method is most likely manual. In such case, the attacker
drops the malware on an already compromised machine.
The malware configuration is stored encrypted in the registry, unlike most Lazarus malware that come
with an encrypted file as configuration. In our case, the configuration data could not be retrieved as
it was fully erased before the investigation began by the attackers that didn’t need this component
anymore since the ~~SQCSVC~~ RAT was installed.
The malware uses different kind of encryption for different kind of purposes. The first substitution-based
encryption is used for decrypting encrypted strings in the static binary. The XOR-based encryption is used
to obfuscate communications between the server and the client and to decrypt configuration content
such as the Command-and-Control (C&C) server name and port number stored in the Windows registry.

### Overview of the Lazarus Group Attack Analysis

#### 1. **Initial Infection and Persistence**
- **IGFX Tool**: 
  - Compiled on Monday, May 02, 2016 UTC.
  - Purpose: Forward traffic to another infected host to relay operators' commands.
  - Contains non-native Russian strings to confuse attribution.
  - Uses a static version of libcurl v7.49.1, common among Lazarus samples.

- **SQCSVC RAT**:
  - Compiled on Saturday, November 03, 2018 UTC.
  - Packed using Themida Code-Virtualizer, but the payload code can be easily dumped from memory.
  - Similar to IGFX tool (65% similarity) and a sample described by TrendMicro after a Lazarus bank heist in Latin America in November 2018.

#### 2. **SQCSVC Configuration and Functionality**
- **Configuration**:
  - Encrypted configuration file: `sqcsvc.dll.mui`.
  - C&C addresses: `member.itemdb.com` and `180.235.132.206`, both on port 443.
  - Uses Fake-TLS protocol for communication.

- **Functionality**:
  - Download and write files to disk.
  - Execute files or bash commands.
  - Inject code into a running process.
  - Listen to commands on a specified port (server mode).
  - Rewrite the configuration file with new values.

#### 3. **SWPSVC (Stage 1)**
- **Description**:
  - Reconnaissance malware implementing Remote Administration Tool features.
  - Loaded by `svchost` service and registered as an AUTO_START service for persistence.
  - Configuration stored encrypted in the registry, but fully erased by attackers before investigation.

- **Encryption**:
  - Substitution-based encryption for decrypting static binary strings.
  - XOR-based encryption for obfuscating communications and decrypting configuration content.

- **Commands Implemented**:
  - Get system information (processor architecture, network interfaces).
  - Write, read, delete files.
  - Get process info, kill processes, create processes.
  - Execute processes as a given user.
  - List files in a directory.
  - Modify C&C configuration.
  - List local drives and network shares.
  - Move files.

#### 4. **Downloaded Modules**
- **Injector**:
  - Injects a file into an `explorer.exe` process, executed in a new thread.
  - Uses RC4 encryption with the hardcoded key "key" to hide suspicious strings.
  - Writes log data to `C:\windows\temp\temp0917.tmp`.

- **Keylogger and Screencapper**:
  - DLL named `capture_x64.dll` by attackers.
  - Implements standard keylogging and screencapping features.

#### 5. **Detection and Mitigation**
- **YARA Rules**: 
  - Provided to the client to detect all discovered payloads.

- **PowerShell Script**: 
  - Automates deployment of detection rules.

- **Suricata Rules**:
  - Detects Lazarus fake-TLS and custom protocol traffic.
  - Can be used with a Python script to decrypt packets.

### Conclusion
The attack by the Lazarus group involved multiple stages, from initial infection using tools like IGFX to deploying sophisticated RATs like SQCSVC and SWPSVC. The use of advanced encryption techniques and persistence mechanisms highlights the sophistication of the attackers. By providing YARA rules, a PowerShell script for deployment, and Suricata rules for detection, the client was able to effectively stop the attack and identify all infected machines.
