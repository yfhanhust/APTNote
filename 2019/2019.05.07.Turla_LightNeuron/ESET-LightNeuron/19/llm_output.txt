Two main components comprise LightNeuron: a Transport Agent [18], registered in the Microsoft Exchange

4.1 Microsoft Exchange architecture
Microsoft Exchange allows extending its functionalities using Transport Agents that can process and modify
all email messages going through the mail server [18] . Transport Agents can be created by Microsoft,
third-party vendors, or directly within an organization.
They have many legitimate purposes, such as:
   - Filtering spam


   - Filtering malicious emails/attachments


   - Adding a corporate signature at the end of every email

The typical events handled by a Transport Agent occur when the mail server sends or receives an email.
Before the event is actually executed, the Transport Agents are called and have the possibility to modify
or block the email.

Backdoor
The command handler is actually the implementation of a backdoor controlled by email.
It has the following properties:
   - Depending on the rules, the commands are hidden in a PDF or a JPG attachment.


   - It uses steganography to hide data in PDF documents or JPG pictures.

   - The email is blocked so it will not be delivered to the final recipient.

Although this may sound very similar to the Turla Outlook backdoor controlled by PDF attachments
that we analyzed in 2018 [16], the format of the attachment is quite different. Thus, we believe a different
programmer or team developed it.
As shown in the configuration example, the rule to execute the command handler applies to every
attachment of type image/jpeg going through the Exchange server. It is not very efficient, as most of the
images do not contain commands. As an example, for one victim, the command handler processed around
7000 pictures while only 178 actually contained commands for the backdoor.
Every time the handler is called, it will first check whether the attachment is a PDF document or a JPG image,
as shown in Figure 17.

In the case of a PDF document, the routine first checks for a signature by performing XOR operations
with the data from offset 0x0B to offset 0x10. One way to satisfy this signature condition is by setting

JPG
In case of a JPG image, it first computes a signature using 16 bytes from the first quantization table.
The quantization table is a part of the JPG format and contains data used during the compression of the picture.
It performs several XOR operations on these 16 bytes and compares the result against a hardcoded
signature, as shown in Figure 21.
Figure 21 // Validation of the JPG signature (HexRays output)
We can view these multiple XOR ( ) operations on the input, followed by a comparison, as a set
of mathematical equations:
input 0 input 4 = 250
input 1 input 5 = 16
input 2 input 6 = 82
input 3 input 7 = 145
input 0 input 10 = 40
input 1 input 11 = 219
input 2 input 12 = 213
input 3 input 13 = 176
Once we have the set of equations, we can easily solve it manually or use a SMT (Satisfiability Modulo
Theories) solver such as Microsoft Z3 [20] to find out whether a solution exists and, if so, to find one possible
solution. It turns out this set of equations is solvable and we use the solution to create a JPG image
that can pass the check.
If the previous equation is satisfied, it gets the length of the container from offset 0x0F of the quantization table.
Finally, it extracts the container from the last Start of Scan section, another standard field of the JPG format.

### Overview of Turla's LightNeuron Malware

**LightNeuron** is a sophisticated piece of malware developed by the Turla group, known for its advanced and stealthy techniques in targeting and compromising email servers. The malware primarily targets Microsoft Exchange servers, allowing attackers to intercept, modify, and exfiltrate emails without detection.

### Key Features and Functionality

#### 1. **Transport Agent and Companion DLL**
- **Transport Agent**: This component is installed on the Exchange server and processes incoming and outgoing emails.
- **Companion DLL**: A helper library that performs various malicious activities, including logging, command execution, and data exfiltration.

#### 2. **Customizable Configuration**
- The malware's behavior can be highly customized through a configuration file, allowing attackers to tailor it to specific targets.
- Key parameters include:
  - `SEND_TIME` and `SEND_AT_NIGHT`: Control the timing of data exfiltration.
  - `SEND_FILE`: Specifies files to be automatically exfiltrated.

#### 3. **Logging Mechanism**
- Extensive logging is used for debugging and monitoring.
- Log files are encrypted with AES-256, ensuring that sensitive information remains protected.
- Each log entry has a structured format, including fields such as `log_code`, `hex_value`, and `data`.

#### 4. **Command and Control (C&C) Protocol**
- Supports both JPG and PDF attachments for command execution and data exfiltration.
- Commands are encrypted and embedded in these attachments to avoid detection.
- The malware can execute a variety of commands, including running system commands, exfiltrating files, and modifying emails.

#### 5. **Stealth Techniques**
- **Anti-Replay Mechanism**: Prevents duplicate command execution by logging unique `CmdId` values.
- **Pickup Folder Abuse**: Uses the Exchange Pickup folder to send emails without triggering security checks.
- **Encrypted Communication**: Ensures that all communication between the malware and the C&C server is encrypted.

#### 6. **Handlers and Exfiltration**
- **Handlers**: Perform specific tasks such as logging, command execution, and data exfiltration.
- **Exfiltration**: Data can be automatically exfiltrated based on configuration settings. The zip handler archives emails but does not implement exfiltration mechanisms, suggesting the need for manual or automatic exfiltration.

### Evolution and Variants

#### 1. **Development Effort**
- Function names in the .NET Transport Agent have been obfuscated to evade detection.
- Different samples have unique Indicators of Compromise (IoCs), such as mutex names, log file names, and AES keys.
- Older versions supported only JPG attachments for C&C communication, while newer versions support both JPG and PDF.

#### 2. **Linux Variant**
- Decrypted strings in the Windows DLL suggest a possible Linux variant of LightNeuron.
- These strings include references to Unix commands like `sendmail` and mail servers like Postfix, indicating that the malware may also target Linux-based email servers.

### Impact and Mitigation

#### 1. **Impact**
- Compromises the integrity and confidentiality of emails.
- Allows attackers to maintain persistence on the network by controlling the email infrastructure.
- Can be used for espionage and data exfiltration.

#### 2. **Mitigation**
- Regularly update and patch Exchange servers.
- Implement strong access controls and monitoring for email server activities.
- Use intrusion detection systems (IDS) and security information and event management (SIEM) tools to detect suspicious behavior.
- Conduct regular security audits and vulnerability assessments.

### Conclusion

Turla's LightNeuron malware is a highly sophisticated threat that leverages advanced techniques to compromise and control email servers. Understanding its features, evolution, and potential variants is crucial for organizations to develop effective defense strategies against such threats.
